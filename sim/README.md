# Simulator

Runs the shared `ui/` code in a 240x320 SDL window. Needs cmake, a C++17 compiler, SDL2 and libcurl dev packages.

- Build: `cmake -S sim -B build/sim && cmake --build build/sim -j`
- Run: `./build/sim/sim` (mouse acts as touch; `--scale N` enlarges the window, default 2, LVGL stays 240x320). Shows the demo data (a live Arsenal v Chelsea and the other mockup matches); `--fixtures` loads `contract/fixtures` instead, `--assets DIR` changes the image directory (default `sim/assets`).
- Screenshot: `./build/sim/sim --snapshot out.png` renders once without a window and writes a 240x320 PNG. `--screen matches|news` shows that tab, `--screen live-last` shows the Live tab's last-result card (the favourite keeps only its finished demo matches; `live-last-away` makes that result a 0:2 away defeat, still read favourite first), and `--screen detail|summary|pitch|stats` opens the match detail first (default `live`), and `--match ID` picks the match (default: the live demo match; `demo-rma-bar` is a pre-match without lineups).
- Goal celebration: in the window, `g` makes the favourite score in its live demo match and `w` ends that match with the favourite ahead (full-time win); both run the whole path (source, poll, goal detector, celebration). `--demo-goal` scores automatically 6 s after start, `--reduced-motion` shows the static version. `--screen goal|goal-win` with `--snapshot` renders the celebration after `--at-ms N` ms of animation (default 900).
- Settings: the gear at the top right of the Live tab opens Settings. Choices are saved to `~/.config/soccer-display-sim/prefs.txt` (or `--prefs FILE`; `--prefs memory` keeps them for one run, `--reset-prefs` starts clean). `--fav ABBR` makes a demo team the favourite before start (for example `--fav CHE` or `--fav TOT`, to see their brand colours), and `--live-vs H,A` turns the demo live match into H v A with H as the favourite (for example `--live-vs CHE,EVE`). Snapshots use memory prefs unless `--prefs` is given. `--tz ZONE` sets the time zone (otherwise the first run picks the zone matching the computer) and `--now EPOCH` fixes the clock. `--screen settings|zone|picker|picker-search` renders Settings, the zone list, the team picker, or the picker with "ars" typed and the keyboard up. Brightness and night dimming darken the window with an overlay.
- Wi-Fi: a mock Wi-Fi service with demo networks (`HomeNet-5G` and `Lab-Guest` saved, `HomeNet-5G` joined; scans and joins take about a second so the spinners show). Settings has a Wi-Fi row that opens the network list. Typing `homehome1` joins `HomeNet-5G` and `netgear123` joins `NETGEAR-4F`; anything else fails. `--wifi-saved none` starts with nothing saved, so the guided first-start setup opens; `--wifi none` runs without Wi-Fi (no row, no setup). `--screen wifi|wifi-first|wifi-password|wifi-failed|wifi-connecting` renders the network list, the guided setup, the password page, a wrong password and a join in progress.
- Live data: `--helper URL --token T` (or `HELPER_URL` / `HELPER_TOKEN` in the environment) fetches from the helper over libcurl instead of the demo data; the token is never printed. Every mode goes through the same Poller: matches every 25 s while a match is live, every 3 min otherwise, backing off after failures; news every 5 min. `--offline-test` keeps the demo source down most of the time (1 match poll in 5 succeeds) so the stale marker on the Live tab and the data line at the bottom of Settings ("Cannot reach the helper") can be checked. The demo keys `g` and `w` only work on the demo data. With `--helper`, crests, news photos and cutouts are downloaded through the helper too (`/api/img`, `/api/cutout`, over a second connection so pictures never queue behind data polls) instead of read from `--assets`; control characters in the URL or token are refused at startup. Prefer the environment variables to the flags: `HELPER_TOKEN=... HELPER_URL=https://... ./build/sim/sim`, because command-line arguments are visible to every local user (`/proc/<pid>/cmdline`, `ps`). Use an `https://` URL for real use (plain `http://` is only for a helper on localhost); the simulator prints only the URL's scheme and host, never userinfo (`user:pass@`), the path or a query string. A successful Wi-Fi join (in the mock) asks the Poller to fetch matches, and teams and news when missing, at once.
- Battery: a scripted battery, 78 % on battery by default. `--battery P` (on battery), `--battery P,charging` or `--battery none` sets it; `b` in the window steps through 78 %, 40 %, 18 % (low), 8 % (critical), 55 % charging, 100 % charging and no battery, printing each in the terminal. `--battery-mv MV` instead feeds a pretend ADC reading through the real `BatteryModel` once a second (smoothing, percent, charging inferred from the trend); `+` and `-` move it by 50 mV, as plugging or pulling a charger would, and the terminal shows what the model makes of it. A battery at 15 % or less raises the low-battery banner at start. For snapshots, `--banner low|critical` forces the banner and `--banner none` removes one raised at start (to see the icon), `--stale-min N` renders N minutes after the last update (the stale marker), and `--screen settings-about` shows Settings scrolled to the Battery line.
- Test: `ctest --test-dir build/sim --output-on-failure` (headless, no window needed)
- Fonts: `ui/fonts/gen.sh` regenerates the committed font C files (needs node and python3).
